# 本地识字、抠图与按需拆层实验版

整图生成保持原流程。识字和抠图不调用 Codex；拆层通常使用一次 Codex 语义分析区分主体和装饰，本地模型负责蒙版和背景修复。明确的不可靠物体范围允许最多一次语义纠正，再次失败返回错误且不保存半份结果；环境缺失和其他异常不触发纠正，也没有通用生图降级兜底。

本次替换的是“编辑文字 → 直接编辑”、抠图和拆层三个功能；AI 改图、无痕消除、无痕改字、AI 超清与 AI 扩图仍调用 Codex 生图，详见 [功能与处理方式](creation-tools-contract.md#功能与处理方式)。本地专用模型也是 AI，运行消耗本机 CPU、内存和处理时间；LaMa 会补全缺失背景，不能找回真实的被遮挡像素。

## 安装

安装 uv 后，在项目目录执行 `./scripts/setup-image-tools.ps1`。脚本在 `data/runtimes/image-tools/venv` 创建 Python 3.12 环境，安装 CPU 推理依赖、固定版本 SAM 2 源码及模型；模型下载逐项核对 SHA256，已匹配的文件复用。约需 608 MB 模型存储，加上 Python 与推理依赖空间。运行时不联网下载模型。

默认使用项目 `data/runtimes/image-tools`，可通过 `PHOTO_STUDIO_IMAGE_TOOLS_DIR` 指定已安装运行环境。测试数据目录与模型目录独立；不需要 Docker、API Key 或本地扩散生图模型。系统需要编辑器白名单内的可用字体。

环境和权重安装完成后，直接编辑文字、抠图处理本身无需联网或 Codex 账户额度；完整拆层仍因语义分析需要联网、可用的 Codex 登录及账户额度。模型安装首次下载需要联网。

## 处理流程

- 编辑文字 → 直接编辑（`recognize-text`）：PP-OCRv5 检测和识别文字行；低置信度拒绝处理。OpenCV 根据局部颜色和形态提取笔画，扩张覆盖抗锯齿和边缘，LaMa 在带上下文的局部区域补全背景；大区域限制推理分辨率后映射回原尺寸，未选中区域逐像素保留。清字后再次检测处理区残字；倾斜文字先校正，再比较实际字形、粗体和斜体候选，保存独立文字层。仅可靠的线性字色保存可选 `fillGradient`，纹理字色不强制变为渐变。与调用 Codex 重绘位图文字的“无痕改字”分别处理。
- 抠图：BiRefNet 小模型输出前景透明度，保留原图 RGB，透明度与原 Alpha 相乘。不会重新绘制商品。
- 拆层：先清字，再经统一提供者做一次 Codex 语义分组（最多 8 项）；只提取有明确轮廓的前景物体，环境光效、倒影与地面纹理保留在背景。SAM 2.1 以每项包围框分割，BiRefNet 对带上下文的每个元素分别细化透明度，避免整图显著性只保留主商品；重叠透明度限制重复占用。背景修复使用完整物体轮廓与透明度选区的并集，避免玻璃内部因透明而留下轮廓；大面积缺口保留全局上下文，接缝过渡仅限蒙版内部。完整邻接环均为近似同一纯色时直接补该纯色，其余使用 LaMa。结果按背景、商品/装饰、文字排列。
- 所有处理继续使用已有队列、SSE、停止、重试和完成时事务。成功前校验结果格式、尺寸、坐标、字体白名单和真实图片来源。

## 许可与模型来源

- RapidOCR 与 PaddleOCR：Apache 2.0；PP-OCRv5 ONNX 由 RapidOCR 固定版本模型仓库提供。
- BiRefNet：MIT，使用作者发布的 `BiRefNet-general-bb_swin_v1_tiny-epoch_232.onnx`。
- SAM 2.1：官方代码与模型 Apache 2.0，使用 tiny 权重和固定源码提交。
- OpenCV：Apache 2.0。
- LaMa：原项目代码 Apache 2.0；本版使用 IOPaint 项目维护者提供的固定 SHA256 TorchScript 转换权重。对外打包或商用分发前仍需确认该具体转换权重的授权并附上依赖版权说明，本版不把权重提交版本库。

官方项目：<https://github.com/RapidAI/RapidOCR>、<https://github.com/PaddlePaddle/PaddleOCR>、<https://github.com/ZhengPeng7/BiRefNet>、<https://github.com/facebookresearch/sam2>、<https://github.com/advimman/lama>、<https://github.com/Sanster/IOPaint>。

## 验证边界

文字识别和原字体恢复是不同问题。装饰性花字、发光字、弯曲字和透视文字仍可能不能准确复现。局部形态蒙版在纹理密集背景上可能包含背景细节；OCR 残字检查不能代替视觉接缝检查。BiRefNet 和 SAM 2 的预测不是完整图层语义，也不能恢复被遮挡的原内容；大面积移除、玻璃、烟雾、倒影和阴影需要单独验收。

至少验证中文、英文、渐变、纹理、斜字、无文字和多元素样本，记录处理耗时、正确内容、保留区像素、清字残留、分层重合与背景效果。验收资料保存到独立运行目录；不得以一张样图通过宣称通用效果达标。

## 已知问题

2026-10-07 真实 CPU 模型复测资料位于 `data/runs/local-quality-goal-20261007/accepted`：中文、英文、粗斜体、旋转、线性渐变、纹理字色、无文字、手机海报、多元素、透明材质、投影与遮挡样本的内容和像素不变量检查通过。Chrome 实际绘制的四种中文字样补验位于同目录上级的 `chinese-browser-extra/final-report.json`；普通与粗体额外回归位于 `chinese-regression-final`。这些拆层效果测试指定物体区域，不能代替 Codex 语义分析及页面完整链路的验收。

当前手机海报主体轮廓和玻璃底图残影已改善，倒影、投影按契约保留为环境背景；复杂背景补全仍非真实场景还原。副标题可能拆为多个文字层，OCR 可能漏掉中文空格，原字体家族、渐变端点和装饰字样仍为估算；例如斜体中文样本保留斜体但字体家族可能变化。独立遮挡元素只提取可见部分，不补出被遮挡的商品内容。历史资料保留在 `data/runs/local-tools-check`。

2026-10-10 补充小物体内部正点与邻物负点细化、普通候选的定位范围约束，改善咖啡豆截断和杯碟缺失；不放宽置信度与截断校验。两组已知咖啡语义范围及玻璃、多元素、遮挡的最终本地回归通过像素不变量检查，证据在 `data/runs/creation-continue-20261010/evidence-regression.json`。新完整任务仍可能因语义框跨邻物而失败，主碗背景残影仍未通过视觉验收；处理成功、原像素保留和视觉效果分别判断，最新问题见 [剩余事项](../handoff.md)。
