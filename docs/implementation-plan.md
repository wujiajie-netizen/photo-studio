# MVP 实施计划

## 阶段 1：项目骨架

- 建立前后端与公共包目录
- 配置 TypeScript、代码检查和 SCSS
- 建立 SQLite、本地数据目录和启动脚本
- 完成首页框架、导航和基础设计变量

完成标准：本地一条命令启动前后端，页面可访问，基础数据可持久化。

## 阶段 2：Codex Agent 最小闭环

- 实现 `AgentModelProvider` 和 `CodexCliProvider`
- 检测 CLI 安装、登录和运行失败状态
- 建立 LangGraph 基础流程
- 实现结构化输出、事件归一化和 SSE 推送
- 完成首页 Agent 对话、追问和任务状态展示

完成标准：用户输入电商需求后，系统可返回结构化计划并保存会话。

## 阶段 3：AI 商品图流程

- 完成商品上传与素材预览
- 建立主体处理、场景配置和生成参数页面
- 接入本地模拟生成工具
- 完成任务进度、结果列表、重试、保存和导出

完成标准：完整走通上传到结果保存的流程，不要求首版具备真实高质量生图模型。

## 阶段 4：商品套图与详情页

- 实现平台、地区、语言和比例配置
- 实现卖点输入与 Codex 辅助整理
- 实现套图结构和详情模块选择
- 支持批量任务、单图重试和整套导出

完成标准：两条电商核心流程可以独立运行，也能由 Agent 调度。

## 阶段 5：基础编辑器

- 图片、文字和图层
- 移动、缩放、旋转和对齐
- 撤销、重做和自动保存
- 生成结果进入编辑器并导出

完成标准：用户能够对生成结果完成基础修改并输出可用图片。

## 阶段 6：稳定性与真实图片引擎

- 使用本机已登录的 Codex CLI 内置生图能力，不安装本地扩散模型作为运行依赖
- 通过统一提供者接入真实生图，替换模拟工具，不改变业务接口
- 增加任务恢复、并发限制、超时和错误诊断
- 完成关键流程验收与必要构建检查

完成标准：核心商品图、套图与详情模块能够使用 Codex 真实生图执行，失败可定位和恢复。

用户于 2026-10-05 明确要求生图使用 Codex。商品图、套图、详情模块与 Agent 闭环已通过真实 Codex 调用验收。此前下载的 OpenVINO 模型保留在本地数据目录，不再作为项目生图依赖。

## 当前执行顺序

2026-10-06 新流程结构已由用户确认：素材和提交项目可空，参数接口返回 `{ steps: AgentStepInput[] }`，先显示方案再点击生成。当前优先完成创作页同页执行、文字与素材两种输入、自动项目保存、对话缩略图联动画板和选中图继续创作；验证使用独立数据目录，旧记录与任务恢复不改写、不自动重跑。

阶段 1 至 6 已实现；阶段 4 至 6 的业务字段由用户确认后开发。完整流程验收记录见开发说明，历史阶段记录保留当时的实现边界。
